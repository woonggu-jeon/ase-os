# **Purpose**

이 문서는 ASE-OS의 핵심 가치를 정의한다.

Core Value는 조직 문화나 슬로건이 아니다.

모든 설계, 구현, 리뷰, 의사결정에서 우선순위를 결정하는 기준이다.

어떤 상황에서도 Core Value와 충돌하는 결정은 다시 검토해야 한다.

# **Value 1. Truth Over Assumption**

추측보다 사실을 우선한다.

모든 판단은 확인 가능한 근거를 기반으로 한다.

알지 못하는 것을 아는 것처럼 말하지 않는다.

**Expected Behaviors**

- 근거를 명시한다.
- 불확실성을 표현한다.
- 사실과 의견을 구분한다.
- 출처를 남긴다.

# **Value 2. Design Before Code**

구현보다 설계를 먼저 한다.

좋은 코드는 좋은 설계의 결과다.

설계 없는 구현은 기술 부채를 만든다.

**Expected Behaviors**

- 문제를 먼저 정의한다.
- 대안을 비교한다.
- 구현 전에 구조를 검토한다.

# **Value 3. Knowledge Is an Asset**

지식은 가장 중요한 자산이다.

코드는 변경되지만,

지식은 프로젝트를 이어준다.

**Expected Behaviors**

- 중요한 결정을 문서화한다.
- 중복 지식을 만들지 않는다.
- 경험을 재사용 가능한 형태로 남긴다.

# **Value 4. Explain Every Decision**

모든 중요한 결정은 설명 가능해야 한다.

“좋아서”, “익숙해서”는 충분한 이유가 아니다.

**Expected Behaviors**

- ADR을 남긴다.
- Trade-off를 기록한다.
- 선택하지 않은 대안도 기록한다.

# **Value 5. Long-Term Thinking**

지금보다 미래를 위해 설계한다.

단기 생산성보다 장기 유지보수를 우선한다.

**Expected Behaviors**

- 확장성을 고려한다.
- 교체 가능성을 유지한다.
- 특정 기술에 종속되지 않는다.

# **Value 6. Simplicity Wins**

단순함은 경쟁력이다.

복잡함은 비용이다.

복잡한 설계는 반드시 그만한 이유가 있어야 한다.

**Expected Behaviors**

- 최소한의 구조를 선택한다.
- 불필요한 추상화를 만들지 않는다.
- 중복보다 단순한 구조를 선택한다.

# **Value 7. Continuous Improvement**

완성보다 개선을 선택한다.

ASE-OS는 끊임없이 진화하는 시스템이다.

**Expected Behaviors**

- 회고를 수행한다.
- 피드백을 반영한다.
- 더 나은 방법이 있다면 변경을 두려워하지 않는다.

# **Decision Priority**

가치가 충돌하는 경우 다음 우선순위를 따른다.

1. Truth Over Assumption
2. Design Before Code
3. Knowledge Is an Asset
4. Explain Every Decision
5. Long-Term Thinking
6. Simplicity Wins
7. Continuous Improvement

# **Anti Values**

ASE-OS는 다음 행동을 지양한다.

- 근거 없는 주장
- 문서 없는 중요한 변경
- 설계 없는 구현
- 특정 AI에 대한 의존
- 중복된 지식
- 과도한 추상화
- 단기적인 편의만을 위한 설계

# **Success Criteria**

Core Value가 조직에 정착되었다면 다음이 자연스럽게 이루어진다.

- 중요한 설계 이유를 누구나 이해할 수 있다.
- AI와 사람이 동일한 기준으로 판단한다.
- 프로젝트가 커져도 일관성이 유지된다.
- 지식이 사람에게 의존하지 않는다.

# **Review Checklist**

- 각 가치가 실제 행동으로 이어지는가?
- 가치 간 우선순위가 명확한가?
- 추상적인 표현에 머물지 않는가?
- 장기적인 운영 기준으로 사용할 수 있는가?
